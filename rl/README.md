# 코윅윅 잔차 RL — 1단계 (속도 잔차)

**세팅 완료 + 동역학 랜덤화 구현 완료 (2026-08-21, 사용자 승인 B).**
학습은 8장 명령 한 줄로 시작한다.

---

## 1. 무엇을 학습하는가

`racer-v64` 위에 **속도 잔차 1차원**만 얹는다. 조향은 건드리지 않는다.

근거는 실측이다. 주행 중 1375틱 상한 귀속:

| 상한 | 비중 |
|---|---|
| `V_MAX` (0.90) | 34.6 % |
| 콘 회피 0.45 그룹 | 26.5 % |
| 라이다 프리브레이크 (0.40/0.55) | 30.8 % |
| 콘 접근 0.60 | 5.7 % |
| **횡가속 곡선** | **1.7 %** |

**코너 물리는 94.7 % 구간에서 제약이 아니다.** 우리를 느리게 하는 것은
보수적 상한 상수들이므로, 학습할 자유도는 "어떤 조건에서 상한을 얼마나 풀까"다.
조향 잔차는 결승선 신뢰성 게이트를 통과한 뒤에만 붙인다.

## 2. driver.py 를 건드리지 않는다

`/speed` 퍼블리셔만 가로채 `base + residual` 을 대신 낸다.

```
action 0  →  잔차 0  →  정확히 racer-v64
```

검증 완료:
- `TEST 1  zero residual  |cmd-base| max = 0.00e+00`  (PASS)
- 러너를 잔차 0 으로 태워 **심판 채점 3/3, 평균 51.24, 전부 페널티 5.0
  @ (0.90~0.91, 4.8x)** — v64(51.05~51.18) 와 같은 패턴·같은 자리

`driver.py` 에는 계측 dict 한 곳(`self.last_tick`)만 추가돼 있다. 아무도 읽지
않는 순수 대입이고, **동작 불변을 실측으로 확인**했다:
- `score_now` ok 235 (v64 와 완전 동일)
- 예선 3런 평균 51.05, 페널티 3/3 정확히 5.0

## 3. 관측 — 그라운드트루스를 하나도 넣지 않는다

정책이 보는 것은 **베이스 제어기가 카메라·라이다에서 이미 뽑는 값 + 자기 명령
이력**뿐이다. 절대좌표·오도메트리는 물론이고 `route.json` 유래 값(경계까지
여유 등)도 뺐다 — **실차에 없는 정보에 의존하면 sim-to-real 이 죽는다.**

한 틱 23차원 × 최근 3틱 = **69차원**:
```
speed/V_MAX, steer/MAX_STEER, aim, carea, arc_safe, fmin,
lbias, pass_hold, pass_side, ncone, frame_age, green,
prev_a                                   <- 직전 행동 (정규화 잔차)
+ 활성 상한 one-hot 10종
  (vmax, alat, cone_slow, cone_near, arc_short, checker, lidar1, lidar2, sharp, crawl)
```
`prev_a` 는 2026-08-21 전수검수에서 추가했다. 보상에 `W_SMOOTH·(a−prev_a)²`
항이 있는데 **정책이 자기 직전 행동을 볼 수 없어** 그 항을 원리적으로
최적화할 수 없었다 — 벌점만 받고 줄일 방법이 없는 잡음이었다.
`speed` 는 **base 명령**이라 잔차가 얹히기 전 값이므로 대체가 안 된다.
⚠️ `run_policy.py` 가 **똑같이** 채운다 (`test_env_dyn` D4 가 소스로 검사).
상한 one-hot 이 중요하다: 같은 0.45 라도 콘 회피인지 결승 밴드인지 구분하지
못하면 정책이 같은 행동을 낸다.

경계까지 여유(`room`)는 **보상 계산에만** 쓴다. 학습 중 시뮬에서만 필요한 값이다.

## 4. 행동

```
a ∈ [-1, +1]  →  잔차 = a × 0.35 m/s
최종 명령 = clip(base + 잔차, 0, 1.40)     ← 하드 클립
```
대칭인 이유: `a=0` 이 정확히 v64 라서 SAC 초기 정책이 검증된 지점에서 출발하고,
실차에서 이상하면 잔차만 끄면 된다.

---

## 5. 보상 — 공식 점수의 초 단위 비용

```
r = 0.1 × (1.0 × ds − C)
C = dt + 5·I_off + 5·I_cone + dt·(2·B_edge + 3·B_cone) + 0.01·(Δa)²
```
- 공식 계수(이탈 5초 / 콘 5초)는 **고정**하고 dense 항은 보조로만 쓴다
- `B_edge` 는 공식 한계(반폭+0.12)보다 4 cm 안쪽부터 2차로 커진다 —
  정책이 한계에 붙어 살지 않게 한다
- `B_cone` 은 접촉 반경 0.1525 m 바깥 10 cm 부터 — **좁은 쪽 4.1 cm 틈으로
  비집는 행동**을 진행 보상이 정당화하지 못하게 한다
- 중심선 추종 보상, 큰 조향 벌점, 속도 명령 자체 보상은 **넣지 않는다**

**진행량 `ds` 는 선분 사영으로 낸다.** 웨이포인트 간격이 0.1 m 라 최근접
웨이포인트의 arc 값을 쓰면 진행이 0/0.1/0.2 계단이 되어 신호가 깨진다.
(초기 구현이 실제로 그랬고, 153 샘플 사영 검증으로 고쳤다 — 비단조 0건,
스텝 평균 0.0130 m)

## 6. 텔레포트

심판은 이탈·콘히트 때 차를 **중심선 0.3 m 앞**으로 옮긴다 (주최측 확인:
*"네 강제 이동 합니다"*). env 도 **같은 규칙으로** 옮겨 학습 분포를 평가와 맞춘다.
그 스텝의 `ds` 는 **0 으로 만든다** — 안 그러면 정책이 "이탈해서 순간이동으로
전진"을 배운다.

## 7. 에피소드

```
리셋      **출발선(wp0)** 에 lat ±0.10 m, yaw ±0.10 rad 로 텔레포트  (~100 ms)
          + cone6 를 뺀 콘 5개 재배치
워밍업    0.25 초 (5틱) — last_tick 을 채우는 최소값
수집      **한 바퀴** (30.505 m), 출발선에서 출발선까지. 안전망 150 초
```

### 워밍업이 1.2 → 0.25 초로 줄어든 이유 (2026-08-21)
1.2 초는 **8 초 슬라이스 시절의 장치**였다. 그때는 매 에피소드가 트랙 임의
지점에 정지 상태로 떨어져서 *"코너 한복판에 서 있다가 출발"* 이라는 **실제
랩에 없는 상태**로 시작했고, 그걸 과학습하지 않으려고 베이스 제어기로 먼저
1.2 초를 달렸다.

랩을 출발선에서 시작하는 지금은 전제가 사라졌다:
- 정지출발이 **심판과 같은 진짜 상태**다 (심판도 출발선 정지에서 시작)
- 비중이 랩당 1회, **870 스텝 중 5틱(0.1 %)** 이라 편향이 될 수 없다

그리고 남겨두면 **해롭다**: 배포 경로 `run_policy.py` 에는 워밍업이 없어
초록불 첫 틱부터 정책이 개입하는데, 학습에서만 랩 시작 1.2 초를 정책이
제어해보지 못한다 (학습/배포 불일치). 게다가 그 구간은 **심판이 시간을 재는
구간**이다. 0 으로 두지 않는 이유는 텔레포트 직후 `last_tick` 이 비어 있으면
첫 관측이 `DEFAULT_LT` 폴백이 되기 때문이고, 5틱이면 채워진다.

### 랩 단위인 이유 (2026-08-21 사용자 지시로 8 초 슬라이스에서 변경)
**이탈하거나 콘을 쳐도 에피소드를 끊지 않는다.** 심판처럼 차를 중심선 앞
0.3 m 로 옮기고 **그 랩을 계속 돈다.** 그게 평가 조건 그 자체다.

바꾼 이유 세 가지:
1. **평가가 랩이다.** 공식 점수는 한 바퀴이고 페널티가 누적된다.
   8 초 슬라이스는 그 구조를 원리적으로 못 본다
2. **결승선 접근은 랩 스케일 사건**이고 그게 지금 1순위 병목이다. 슬라이스로는
   "랩의 끝으로서의 결승선"을 절대 경험하지 못한다 — 우연히 그 5 m 에 스폰될
   때만, 그것도 맥락 없이 본다
3. **리셋 자체가 인공물이다.** 텔레포트는 속도를 0 으로 만들고 워밍업 1.2 초는
   그걸 가리는 장치다. 랩 단위면 리셋이 60k 스텝당 **375 회 → 약 55 회**로 줄어
   인공물이 7 배 줄고 스텝률도 오른다

⚠️ **정직한 한계**: `gamma=0.995` 는 유효 지평이 약 10 초라, 랩으로 바꾼다고
"랩 전체를 내다보는" 추론이 자동으로 생기지는 **않는다.** 이득의 실체는
**분포 일치와 인공물 제거**다. 지평까지 늘리려면 `gamma` 를 따로 올려야 하고
그건 **별도 변경**으로 둔다 (한 번에 하나).

검증: `test_env_dyn.py` TEST G — 실주행 한 바퀴 877 스텝(43.9 초), `lap_s`
30.55 ≥ 30.50, **첫 페널티 236 스텝 → 총 877 스텝**(이탈 3건이 랩을 끊지 않음).
슬라이스로 돌리려면 `--no-lap --episode-s 8`.

## 7b. 동역학 랜덤화 (2026-08-21 구현, 기본 ON)

**에피소드마다 플랜트를 다시 뽑는다.** 근거 코드 `rl/dyn.py`.

### 왜
시뮬 구동계(`gz AckermannSteering`)는 **속도 소스**다 — 감속이 폴 1개
(~0.07 s, **≥4.5 m/s²** 실측) 안에 끝나고 3랩 실주행거리/명령거리 = **0.9968**.
**이 시뮬에서 감속은 공짜다.** 그 위에서 속도 잔차를 학습하면 정책은 반드시
"코너 직전까지 최고속 → 순간 감속"을 배운다. 실차 모터는 그렇게 안 선다 —
작년 RL 모델이 실차에서 전멸한 것이 정확히 이 형태다.
**콘 위치만 랜덤화해서는 이 계통 오차를 못 막는다.**

### 무엇을
| 축 | 범위 | 시뮬 참값 |
|---|---|---|
| 가속 한계 | 1.5~9.0 m/s² | 사실상 무한 (≥4.5 실측) |
| 감속 한계 | 1.0~9.0 m/s² | 〃 |
| 조향 서보 각속도 | 3~12 rad/s | 10 (*"Limit steering joint velocity to 10"*) |
| 구동 지연 | 0~3 틱 (0~150 ms) | 0 |
| 관측 지연 | 0~2 틱 (0~100 ms) | 0 |

가속·감속을 따로 뽑는다 (미는 힘 ≠ 멈추는 힘). **범위가 시뮬 참값을 포함**해야
정책이 지금 성적을 통째로 버리지 않는다. 텔레포트 시 구동 액추에이터는 0 으로
되돌린다 — 심판 텔레포트가 차를 세우기 때문이다(실측).

### 어디에 안 켜는가
`run_policy.py`(배포)와 `eval_policy.py`(공식 채점)는 **참 플랜트**를 그대로
쓴다. 랜덤화는 학습 분포를 넓히는 도구지 평가 조건이 아니다. `--no-dyn` 으로
학습에서도 끌 수 있다 (대조군용).

### 검증 (전부 통과)
```bash
python3 rl/test_dyn.py        # 단위 20건, ROS 없이 몇 초
python3 rl/test_env_dyn.py    # 시뮬 인더루프 8건, 약 2분
```
| | 결과 |
|---|---|
| `dyn=False` 순수통과 | `\|cmd−base\| max 0.0` / `\|cmd_out−cmd\| max 0.0` (160 스텝) |
| 가감속 한계 위반 | **0** / 240 스텝 (단위테스트 200 에피소드도 0) |
| 플랜트가 무는 양 | 평균 `\|cmd−cmd_out\|` **0.041 m/s** |
| 에피소드당 진행 | 2.76 m (off) → **2.00 m** (on) — 약한 플랜트라 덜 간다 |
| 관측 차원 | 66 불변, 전부 유한 |

**끄면 즉시 순수 통과로 복귀한다** (TEST C). 되돌릴 수 있는 변경이다.

### 다음 후보 축 (지금은 안 넣는다)
모터 게인 오차, 조향 트림 바이어스. 실재하지만 **1차원 속도 잔차로는 보상할
수 없는 축**이라 보상 신호에 잡음만 더한다. 조향 잔차(2단계)에서 같이 열 것.

## 8. 실행 (승인 후)

```bash
. /opt/physicar/src/physicar-ros/deploy/sim/bashrc-append
cd ~/physicar_ws/coweek
python3 rl/train_speed.py --steps 60000 --out rl/runs/s1
```

**예산**: 제어 20 Hz, RTF 1.0 이 하드 상한 → **시간당 72,000 스텝**.
시뮬 가속은 쓰지 않는다 — `driver.py` 가 `use_sim_time` 을 안 쓰므로 가속하면
시뮬 시간 기준 제어 주기가 줄어 **다른 플랜트**가 된다.

```
60k  ≈ 50분   |  144k ≈ 2시간  |  216k ≈ 3시간
```

**평가는 학습 곡선이 아니라 공식 채점기로만 한다:**
```bash
python3 rl/eval_policy.py --model rl/runs/s1/final.zip --runs 15 --baseline
python3 rl/eval_policy.py --model rl/runs/s1/final.zip --runs 15 --finals --baseline
```
같은 배치 안에서 정책 vs 잔차0 을 비교하고 Gate F/P/S 를 찍는다.

**실측 스텝률은 16.4~16.5 steps/s** (2026-08-21, 랜덤화 ON). 20 Hz 의 82 % 이고
차이는 전부 에피소드 리셋 오버헤드다 — **RTF 손실이 아니다** (학습 중 실측
`rtf 0.9948`). 그래서 60k 는 **약 61분**이다.

## 8b. 채택 기준 — **학습 결과를 보기 전에 못박는다**

이 프로젝트는 사후에 기준을 고르다 여러 번 데었다 (v67 은 예선 3개 기준을
다 통과하고 본선에서 뒤집혔고, v68 은 오프라인 게이트 셋을 다 통과하고 배치에서
정반대로 나왔다). 그래서 **숫자를 보기 전에** 적어둔다.

### 채택 조건 (전부 만족해야 채택)
같은 배치 안 비교, `--baseline` 필수. **예선맵과 본선 조건 둘 다** 돌린다.

| | 조건 |
|---|---|
| **Gate P 페널티 합** | 정책 ≤ 기준선 |
| **Gate S 평균 점수** | 정책 < 기준선 (낮을수록 좋다) |
| **Gate C 콘 히트** | 정책 ≤ 기준선 |
| **Gate F 결승선 놓침** | 정책 ≤ 기준선 |

### 미리 정한 해석 규칙
- **Gate F 는 증거가 아니라 지뢰선이다.** 기준선이 3 % 라 n=15 로는 못 가른다
  (0/15 여도 실제 9.5 % 가능). **늘면 즉시 기각**, 같거나 줄어도 "개선됐다"고
  쓰지 않는다
- **본선 단독 배치의 절대 수치는 안 믿는다.** 같은 v64 가 세 배치에서 페널티
  130/170/200 이었다. 그래서 **같은 배치 안의 정책 vs 기준선 차이**만 읽는다
- **예선맵만 통과한 것은 통과가 아니다** (v67 이 정확히 그 함정이었다)
- 기각이면 **파라미터를 만지작거려 재도전하지 않는다.** 왜 졌는지 기전을
  먼저 특정한다 — 이 프로젝트에서 성공한 변경은 전부 "이미 있는 측정을
  코드에 반영한 것"이었고, 실패한 것은 전부 "새 메커니즘 발명"이었다

### 채택돼도 남는 조건
- 배포는 `ACTIVE_MODEL` 파일 하나다. **8/25 실차에서 이상하면 지운다** —
  그 순간 v64 로 복귀한다. 이 롤백 경로를 현장 체크리스트에 넣을 것
- 학습은 **시뮬 플랜트 분포** 위에서 됐다. 실차 가감속을 재고 나면
  `dyn.py` 범위가 맞았는지 확인하고, 크게 어긋나면 **재학습이 아니라 잔차 0**
  으로 간다 (대회 당일에 학습할 시간은 없다)
